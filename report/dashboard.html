How it works

Three steps, run as many rounds as you like.

1 · Attack

A hand-written attack library plus attacks written by Gemma (an open model, run locally) query the warehouse as the analyst role.

2 · Fix

The open pii-guardian skill maps each proven leak to the smallest Snowflake-native fix: a masking policy, a revoked grant, or a dropped copy.

3 · Prove

The referee re-runs every attack and ten legitimate analyst queries. Success means leaks at zero and nothing legitimate broken.

Plugging it into your data platform

Built to run continuously against a real warehouse, not just this dataset.

Connect

Two roles: a low-privilege role to attack as, and an admin role to fix and log. Key-pair auth, no passwords.

Schedule

Run a round after every schema change, grant, or on a timer. Every attack, fix and re-check is stored as an audit trail.

Fix your way

The pii-guardian and Bouncer skills follow the open Agent Skills standard, so any agent or a plain script can apply the same playbook.

Extend

Attacks and legitimate checks are plain YAML. Snowflake today; the attack, fix and prove loop is designed for other warehouses next.
